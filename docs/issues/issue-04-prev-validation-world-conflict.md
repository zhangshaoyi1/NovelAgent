# 问题 #04：pre_validation 拦截 —— 世界观冲突（仙尊 vs 渡劫）阻断章节写入

| 项 | 内容 |
|---|---|
| 分类 | 小说生成 / 一致性 |
| 严重度 | 高（硬错误，重试无效，必须人工/半自动解决世界观冲突） |
| 状态 | 已解决（后续批次修正大纲/状态后跑完；内核拦截行为本身保留） |
| 关联文件 | `src/agent/core/...`（pre_validation / 冲突仲裁）、`projects/jipin-yixian/` 的 `outline.md` / 状态机、驱动 `_write_driver_jipin.py`（`_is_hard_error`） |
| 证据 | `_driver_log_jipin.json` 记录 #135：`pre_validation_blocked`，两条严重冲突 |

## 1. 问题描述
NovelAgent 在写章节前有 **pre_validation（预校验 / 冲突仲裁）** 环节，会对照设定集（境界体系、进度规划）检查本章是否引入严重矛盾。极品医仙写到临近结尾时，预校验**拦下了第 50 章**，报告两处严重冲突，导致该章无法写入。

## 2. 现象 / 证据
记录 #135 原文：
```
pre_validation_blocked:
检测到两处严重冲突：
1. 境界体系中"仙尊"与原定最高境界"渡劫"的定义冲突；
2. 第 50 章关联最终决战支线与原定 81 章开启的进度规划严重冲突。
```
驱动侧 `_is_hard_error()` 命中 `pre_validation` 关键字，判定为**结构性硬错误** → `hard_error_skip` → 不再重试（重试无意义，因为是设定冲突而非瞬时故障）→ 该批 `max_retries_exhausted, 中止本批`。

## 3. 根因
- **设定集自相矛盾 / 后期偏离**：前期设定最高境界为「渡劫」，后期剧情又把主角推到「仙尊」层级；进度规划里「最终决战支线」原计划第 81 章才开启，但压缩后的大纲第 50 章就想打终局——规划与执行脱节。
- pre_validation 严格拦截是对的（避免成书出现硬伤），但它**只报错、不提供解决通道**，必须人工改大纲/状态才能继续。

## 4. 解决方案（当前）
- 驱动把这类错误归类为硬错误，**跳过重试**避免空耗（正确做法）。
- 后续批次中，通过修正 `outline.md` / 状态机（允许「仙尊」作为新顶层境界、把终局支线起点前移）解除冲突；小说最终以 51 章 / 176,078 字完结（含 `novel_complete`）。

## 5. 影响
- 若不修正设定，终章无法生成，书会卡在 50 章。
- 暴露了「大纲规划值（81 章开终局）与实际压缩执行（50 章开终局）不一致」这一**规划漂移**问题（与 issue-05 同源）。

## 6. 改进建议
- **冲突可一键仲裁 / 豁免**：提供 `agent.cli adjust-conflict`（或 `write --force`）子命令，把「接受新设定并回填设定集」做成显式动作，并记录到状态机，避免每次都手工改文件。
- **规划值单一来源**：终局支线起点等「进度规划」应由状态机自动推导，不要同时存在于 `outline.md` 文本与代码常量，消除双份真相导致的漂移。
- **早期预警**：在 `adjust-route` 阶段就对「即将越界（如提前开终局）」给出警告，而非等到 `write` 才硬拦。

## 7. 复现 / 验证
- 故意在 `outline.md` 写入与状态机矛盾的境界 / 进度，再跑 `write`，观察 `pre_validation_blocked`。
- 修正后重跑，确认该章可写入（`quality_passed: true`）。
