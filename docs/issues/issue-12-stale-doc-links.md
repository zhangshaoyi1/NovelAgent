# 问题 #12：中文文档中的失效链接（指向不存在的 `docs/ACDEF…md` 等）

| 项 | 内容 |
|---|---|
| 分类 | 文档 |
| 严重度 | 低（不影响运行，仅文档导航断裂） |
| 状态 | 已解决（`说明.md` / `用户指南.md` 修正） |
| 关联文件 | `项目文档/说明.md`、`项目文档/用户指南.md`、失效链接 `docs/ACDEF增量需求文档.md` / `docs/B可视化面板需求文档.md` / `docs/B可视化面板设计.md` |
| 证据 | 编辑 `说明.md` 时 `docs/ACDEF增量需求文档.md` 命中 4 处；同类失效链接多次出现 |

## 1. 问题描述
`项目文档/` 下的 `说明.md`、`用户指南.md` 引用了一批 `docs/*.md` 文件（如 `docs/ACDEF增量需求文档.md`、`docs/B可视化面板需求文档.md`、`docs/B可视化面板设计.md`），但这些文件**在重构后的目录里并不存在**（可能是早期草稿名 / 已被合并），导致文档导航断链。

## 2. 现象 / 证据
- 编辑 `说明.md` 试图替换 `docs/ACDEF增量需求文档.md` 时，工具报告 **Found 4 matches**——说明同一失效链接在文件中出现 4 次（多处互链）。
- 同理 `docs/B可视化面板需求文档.md`、`docs/B可视化面板设计.md` 各出现多次，均失效。
- 还有结构树过时：`根目录 .state/state.json` 应为 `小说/projects/<小说名>/state.json`；`├── agent/ # Python 包` 应为 `├── src/agent/`；`└── state-schema/` 应为 `└── state_schema/`。

## 3. 根因
- 文档在多次重构（改名、目录调整、src 布局）后**未同步更新链接与结构树**，出现「文档描述 ≠ 实际布局」。
- 失效链接多为早期需求文档的旧文件名，重构时被合并进 `系统架构与设计总览.md` 但链接没改。

## 4. 解决方案（当前）
- 用 `replace_all=true` 将 `docs/ACDEF增量需求文档.md`、`docs/B可视化面板需求文档.md`、`docs/B可视化面板设计.md` 全部改为指向 `系统架构与设计总览.md`。
- 更新 `说明.md` 的结构树与状态文件路径描述，对齐 src 布局与项目级 `state.json`。
- 更新 `用户指南.md` 的参考表：`state.json` 路径从 `.state/state.json` 改为 `小说/projects/<小说名>/state.json`。

## 5. 影响
- 纯文档层面；不影响代码运行。但会误导后续维护者，尤其「状态文件在哪、能否手动改」这类关键说明若错，容易导致误操作。

## 6. 改进建议
- **文档与布局变更联动**：每次改目录结构 / 文件名，同步扫一遍文档链接（可用 `grep` 全仓扫描 `docs/` 引用）。
- **加链接检查**：在 `项目文档` 仓库做个简单 markdown 链接校验（CI 或脚本），失效即报错。
- 关键运维信息（状态文件路径、能否手改）在 `README.md` 与 `用户指南.md` 都写明，避免单点失真。

## 7. 复现 / 验证
```bash
# 在 项目文档 仓库扫描失效的相对链接
cd "D:/project/NovelAgent/项目文档"
grep -rn "docs/ACDEF\|docs/B可视化" . --include=*.md
# 期望无输出（已全部改为 系统架构与设计总览.md）
```
