# NovelAgent 系统架构文档

## 一、总体架构原则

### 1.1 高类聚低耦合
- **高类聚**：每个子包（模块）只负责一个明确的职责领域，内部功能高度相关
- **低耦合**：子包之间通过明确定义的接口通信，依赖关系单向、不循环

### 1.2 单向依赖原则
```
entry (cli/__main__.py)
    ↓
workflows/ (工作流编排)
    ↓
agents/ (多智能体团队)
    ↓
core/ 分层：
    ├── story/  quality/  (业务领域层)
    ├── engine/  registry/  infra/  (核心引擎层)
    ├── llm/  (LLM 基础设施)
    └── base/  (基础基础设施)
    ↓
client/ (LLM 客户端)
    ↓
base/ (异常、注册表基类)
```

**核心规则**：下层绝不依赖上层，禁止循环依赖。

### 1.3 新增/修改功能必须遵守的原则
1. **文件归属**：新功能必须放在对应职责的子包中，不得在 core/ 根目录创建文件
2. **依赖检查**：新引入的 import 不得产生循环依赖
3. **单向引用**：下层包不能 import 上层包的内容
4. **接口统一**：所有子包通过 `__init__.py` 导出公共接口，内部实现对外隐藏
5. **文档同步**：新功能需同步更新对应子包的 README.md

## 二、核心分层架构 (core/)

### 2.1 base/ — 基础基础设施层
**依赖**：仅标准库
**被依赖**：所有上层包
**职责**：异常定义、注册表基类、重试机制、结构化输出

### 2.2 engine/ — 核心引擎层
**依赖**：base/、client/
**被依赖**：workflows/、cli/、agents/、infra/、tools/
**职责**：状态机、Agent 循环、**工具契约**（tool_contracts：Tool/ToolRegistry/@tool，实现见 tools/，engine 不依赖实现包）、命令路由、工作流编排、事件流、多 Agent 协作

### 2.3 story/ — 故事领域模型层
**依赖**：base/、client/
**被依赖**：workflows/、agents/、infra/
**职责**：设定管理、伏笔、关系网、章节、高潮曲线、爽点剧本、套路存储
**子包**：story/meta/ — 元设计（世界观 Schema、产品哲学、写作方法论）

### 2.4 quality/ — 质量保证层
**依赖**：base/、client/、story/
**被依赖**：workflows/、cli/、service/、agents/、tools/（懒加载）
**职责**：一致性检查、冲突仲裁（conflict_service，从 infra/ 归位）、架构门禁、质量检查、护栏与全量去重扫描（fullbook_dup_scan）、读者吸引力评分、反馈重写

### 2.5 llm/ — LLM 基础设施
**依赖**：无（不依赖任何其他 core 子包，仅标准库 + 可选第三方）
**被依赖**：client/、rag/（经 embed_fn 注入）、memory/
**职责**：模型路由、预算规划、文本嵌入提供方（embeddings：OpenAI 兼容 / Ollama / Qwen 本地，从 rag/ 归位）、Embedding 路由

### 2.6 registry/ — 扩展机制注册表
**依赖**：base/
**被依赖**：workflows/、cli/
**职责**：技能注册表、题材包注册表、题材合并

### 2.7 infra/ — 基础设施层
**依赖**：base/、client/、engine/（doctor 诊断状态机）、story/
**被依赖**：workflows/、cli/
**职责**：一键写书编排（compose，质量门禁经回调注入）、上下文加载、仪表盘、健康诊断、钩子分发
**注**：冲突仲裁已归位 quality/conflict_service.py（消除 quality ↔ infra 循环依赖）

### 2.8 其他子包
| 子包 | 职责 |
|------|------|
| `rag/` | 检索增强生成（索引、检索、向量存储；embedding 能力经 llm/ 注入） |
| `event_sourcing/` | 事件溯源（事件总线、存储、恢复、事件化重试包装器） |
| `llmops/` | LLM 运营（成本、追踪、评测） |
| `anti_ai/` | AI 味检测与压制 |
| `supervisor/` | 长小说监督体系 |
| `auto_orchestrator/` | 自动编排 |
| `tools/` | 工具实现层（内置工具、MCP 桥接；契约在 engine/tool_contracts，依赖 engine/ + story/ + rag/ + quality/ 懒加载） |

## 三、上层模块

### 3.1 agents/ — 多智能体团队
| Agent | 职责 |
|-------|------|
| `PlannerAgent` | 架构师，产出 Master Plan |
| `EditorAgent` | 主编，一致性仲裁 |
| `EvaluatorAgent` | 评测员，全书"不崩"终审 |
| `WriterAgent` | 自主写章 Agent（Writer + Critic 内联） |

### 3.2 workflows/ — 工作流
| 工作流 | 对应阶段 | 职责 |
|--------|---------|------|
| M1 Config | 配置 | 项目初始化 |
| M2 Discuss | 讨论 | 脉络发散讨论 |
| M14 Architecture | 架构 | 故事架构生成与确认 |
| M3 Outline | 大纲 | 大纲与简介生成 |
| M4 Character | 角色 | 角色路线与关系网 |
| M5 Write Chapter | 写章 | 章节创作（含质量门禁） |
| M6 Adjust | 调整 | 路线/关系动态调整 |
| M8 Mode | 模式 | 介入频率控制 |
| M10 Rollback | 回滚 | 失败回退与续作恢复 |
| M11 Export | 导出 | 导入导出 |
| M12 Audit | 审计 | 内容审核与设定冲突 |
| M13 Foreshadow | 伏笔 | 伏笔管理 |
| M16 Pacing | 追读 | 追读力抽取与对账 |
| M17 Learn | 学习 | 技法提炼 |
| M18 Recovery | 恢复 | 错误恢复 |
| Agentic Write | 写章 | 自主写章（Phase 1） |
| Agentic Pipeline | 全流程 | 全流程自主编排（Phase 2） |

### 3.3 cli/ — 命令行接口
命令注册通过 `@command` 装饰器自动注册到 `CommandRouter`。

### 3.4 client/ — LLM 客户端
统一 LLM 调用入口，封装 provider 选择、结构化输出和 embedding 路由（通过 core/llm/embedding_router 间接调用）。
**依赖**：仅 base/（通过 core/llm/ 间接依赖 rag/embeddings，不直接耦合）

### 3.5 service/ — 服务层
进程内服务接口，供 CLI 和未来 Web UI 共用。

## 五、代码规范

### 5.1 文件组织
- 每个子包必须有 `__init__.py` 导出公共接口
- 每个子包必须有 `README.md` 说明职责和依赖
- 文件名使用小写蛇形（snake_case）
- Agent 文件名使用短名称（如 `planner.py` 而非 `planner_agent.py`）

### 5.2 导入规范
- 优先使用绝对导入（`from agent.core.story.setting_manager import ...`）
- 避免循环导入：如果 A 导入 B，B 不能导入 A
- 延迟导入（lazy import）用于解决不可避免的循环依赖

### 5.3 架构合规
- 所有 Agent 必须继承 `base.Agent` 抽象基类
- 所有 LLM 调用必须通过 `client/LLMClient` 统一入口
- 使用 Registry/Provider/Consumer 模式进行动态加载
