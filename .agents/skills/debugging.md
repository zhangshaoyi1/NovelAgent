# Debugging Skill - 调试方法论

> 目标：将资深工程师的调试经验沉淀为可执行的检查流程。

---

## 调试流程

### Step 1: 复现问题

- 确认问题是否可稳定复现
- 记录复现步骤
- 确认环境信息（Python 版本、依赖版本、LLM 配置）

### Step 2: 缩小范围

- 隔离问题模块：CLI / Workflow / Core / Agent / LLM
- 使用 `pytest -k <test_name> -v` 运行相关测试
- 使用 `--verbose` 或 `--debug` 标志获取更多日志

### Step 3: 形成假设

- 查看错误堆栈，定位到具体文件和行号
- 检查相关模块的测试用例，确认是否为已知问题
- 如果是 LLM 相关错误，检查 `.env` 配置和网络连接

### Step 4: 验证假设

- 编写最小化复现脚本
- 修改代码后运行相关测试
- 确认修改不会破坏其他模块

### Step 5: 最小化修复

- 只修复问题本身，不做不必要的重构
- 遵循"降级不阻断"原则：LLM 不可用时应优雅降级
- 添加回归测试防止再次出现

### Step 6: 验证修复

- 运行 `pytest` 全量测试
- 确认修复在真实场景中有效

---

## 常见问题排查

### 导入错误
- 检查 `src/` 布局和 `pyproject.toml` 的 `where` 配置
- 确认 `pip install -e .` 已重新运行
- 检查是否有循环导入（`base` 依赖上层是最常见的根因）

### LLM 调用失败
- 检查 `.env` 中的 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL_ID`
- 检查 `core/model_routing.py` 的路由配置
- 使用 `LLMClient` 测试连接

### 测试失败
- 确认测试文件在正确的目录下
- 检查 `pytest` 配置
- 使用 `-v` 标志查看详细输出
